# 배포와 검증 계획

배포 기준, MVP 완료 시나리오, 미확정 항목과 구현 순서다.

## 배포와 검증

### 배포 단위

- 클라이언트: Windows·macOS 및 지원 CPU별 설치 패키지. 로컬 KWS 후보 엔진과 별도 한국어 모델, Silero VAD, WASM·네이티브 바이너리를 버전 고정해 포함하거나 검증된 초기 다운로드로 제공한다. 각 엔진·모델·학습 데이터의 라이선스 및 재배포 조건을 개별 확인한다. STT·TTS 모델은 클라이언트에 포함하지 않는다.
- 서버: 모듈을 묶은 API·WSS 애플리케이션 1개, STT·TTS 처리와 MySQL. 인증·외부 API 비밀은 배포 설정에서 주입하고 음성 처리량·자원 사용량을 관찰한다.
- 클라이언트·서버 프로토콜은 버전 관리하고 지원하지 않는 도구·버전은 명확히 거절한다.
- macOS 서명·공증과 Windows 배포·네이티브 모듈 로딩은 실제 산출물 기준으로 검증한다. 마이크 권한·백그라운드 입력·로컬 KWS/VAD 실행과 모델 파일 경로, 서버 STT 업로드·TTS 오디오 재생도 설치 패키지에서 확인한다.

### MVP 완료 시나리오

| 시나리오 | 완료 조건 |
| --- | --- |
| 계정 인증 | [인증 검증](#인증-검증)의 가입·중복 확인·로그인·유지·미로그인 제한·로그아웃·만료·계정 전환을 완료하고 주요 기능이 확인된 사용자에게만 허용됨 |
| 연속 음성 명령 | 대기 KWS가 “자비스”를 감지하고 Ring Buffer로 “크롬 실행해 줘” 시작을 보존. 서버 대화 ID와 요청 ID로 VAD 완료 구간만 전송. 실행 전 응답과 명령별 실제 결과를 구분해 안내 |
| 음성·글 혼합 대화 | 한 대화(`conversationId`)에서 음성 턴과 글 턴이 섞여도 같은 대화로 처리. 음성 세션만 끝나면 대화는 남고, 대화가 끝나면(중지·서버 종료 지시·유휴·로그아웃·일시 중지) 음성 세션도 정리. 처리 중 다른 입력은 거절하고 끝난 대화의 늦은 응답은 적용하지 않음 |
| 후속 발화·무음 | 요청 처리와 TTS 완료 후 호출어 없이 후속 발화 처리. 발화 시작 대기·종료 무음·최대 발화·후속 대기 타임아웃과 빈 STT 결과 검증 |
| TTS 자체 재인식 | 서버 TTS 오디오 재생 중 KWS/VAD가 자체 출력을 요청으로 만들지 않음. 재생 종료 후에만 후속 발화 대기 |
| 음성 전송·장애 | 대기 음성·무음·취소된 구간은 전송하지 않음. 네트워크 단절·STT 실패 시 오디오를 대기열에 저장하거나 자동 재전송하지 않음. TTS 실패 시 텍스트 결과 표시 |
| 음성 중지·권한 철회 | 마이크 중지·권한 철회·취소·일시 중지에서 인식 엔진 정지, 버퍼 폐기, 늦은 결과 무시, 허용될 때만 KWS 대기 복귀 |
| 제스처 | 명시적 시작, 커서 이동, Pinch 1회당 클릭 1회, 최근 작업 전환, 추적 손실 중 입력 없음 |
| 로컬 중지 | 서버 단절·추론 지연 중에도 중지 가능. 누적 이동·클릭이 중지 후 재생되지 않음 |
| 최소 UI | 평소 창 숨김, 상태 표시가 작업 포커스를 빼앗지 않음, 필요한 순간만 입력·확인 창 표시 |
| 상태 독립 | 대화 종료·결과 창 닫기 후에도 제스처·호출 대기가 설정대로 유지 |
| 추천 | 기록 근거가 있으며 승인만 실행. 거절·닫기·만료·중복 승인에서 실행 없음 |
| 일정 | 자체/Google 저장 일정 조회와 Google 연결·해제. 사용자 시간대·종일·반복 일정, 동기화 최신성·인증 오류와 저장 사본의 확정된 처리 정책 반영 |
| 재연결·취소 | 만료·취소 도구 재실행 없음. 결과 불명 시 자동 중복 실행 대신 미확인 처리 |
| 권한·기록 | 권한 거부·철회 안내, 수집 중지·삭제가 로컬 대기열·서버·집계에 반영 |
| 교차 플랫폼 | 위 흐름을 지원 Windows·macOS 실제 환경과 배포 패키지에서 확인 |

성능은 실제 한국어 “자비스” 호출어의 인식률·오호출 수(잡음·TTS 재생 포함), 호출 후 연속 명령 누락률, VAD 발화 시작·종료 지연과 무음 분할 오류, 서버 STT 정확도·왕복 지연, 서버 TTS 생성·재생 시작 지연, 음성 요청 동시 처리량·비용, 영상 입력부터 OS 입력까지의 지연, 추적 손실 후 입력 중단 시간, 대기 중 CPU·메모리·전력으로 측정한다. 목표 수치는 기준 기기와 측정 방법을 정한 후 확정하며, 라이브러리 신뢰도 점수를 실제 성공률로 대신하지 않는다.

### 인증 검증

완료 조건의 원본은 [AUTH-01~07](../features/auth.md)다. 개발용 인증 대역에서는 구현된 로컬 동작을, 실제 서버 어댑터에서는 기기 연결·토큰 교체·입력 정책까지 검증한다. 목표 계약에 추가된 사례가 현재 대역에서 검증됐음을 뜻하지 않는다.

| 시나리오 | 검증 기준 |
| --- | --- |
| 미로그인 시작 | 저장 정보가 없으면 로그인·회원가입 화면만 표시. 일반 설정·대화·센서·KWS·제스처·도구 실행이 시작되지 않음 |
| 접근 우회 | UI를 통하지 않는 IPC·트레이·단축키·도구 실행도 Main에서 차단. 중지·정리·앱 종료는 가능 |
| 입력·가입 | [입력 규칙](../features/auth.md#입력-규칙)의 길이 경계·허용 문자·대소문자 정규화, 비밀번호·재입력 불일치·미확인 아이디를 처리. 가입 성공 후 로그인 화면에 아이디만 유지하고 비밀번호는 비움 |
| 중복 확인 | 아이디 수정·A→B→A 변경·응답 역전·확인 실패를 처리. 확인 후 다른 사용자가 같은 아이디로 가입한 경우 서버가 최종 중복 거절 |
| 로그인 | 성공·잘못된 인증 정보·통신 오류를 구분. 요청 중 중복 제출 방지. 늦은 응답이 로그아웃·계정 전환을 되돌리지 않음 |
| 설치·기기 등록 | 최초 실행 키 저장·재실행 재사용·로그아웃 후 유지. 로그인에 설치·기기 정보를 함께 전달하고 같은 계정의 반복 로그인으로 기기를 중복 생성하지 않음. 다른 계정의 device_id를 재사용하지 않고 로그인 내 등록 실패·지연·계정 전환 중 응답을 처리 |
| 로컬 저장 기반 | 동시 초기화에서 같은 설치 키로 수렴, 재실행 복원, 저장 성공 후 게시, 갱신 실패 시 이전 파일/스냅샷 유지, 손상/미지원 버전·설치 파일 유실의 보존 오류 처리. 초기화 중 종료·재호출 뒤 기능이 다시 시작되지 않음. 파일 규칙은 [원본](../architecture/data-security.md#기기-로컬-저장-형식) 참조 |
| 로그인 유지 | 정상 로그인 후 앱 재실행 시 자격 증명 검증·갱신을 마친 뒤 일반 화면 허용. 저장값이 있다는 이유만으로 주요 기능을 시작하지 않음 |
| 토큰 교체 | [인증 계약](../architecture/server-integration.md#계정-인증-계약)의 만료 경계·동시 갱신 직렬화·교체 자격 증명 저장·이전 토큰 재사용 시 세션 폐기 확인. 응답 유실·저장 실패는 합의한 복구 절차를 따르며 이전 토큰을 자동 재사용하지 않음 |
| 보호 저장 실패 | 저장 불가·읽기 실패·삭제 실패를 알리고 평문 저장으로 대체하지 않음. 로그인·로그인 유지·로그아웃의 실제 완료 여부를 구분 |
| 복구 장애·만료 | 복구 중 네트워크 장애에서는 인증 화면 재시도 제공·주요 기능 차단·저장 정보 무조건 삭제 금지. 명시적 세션 무효·갱신 거절은 정리 후 재로그인 안내 |
| 로그아웃·계정 전환 | 새 실행 차단·기존 세대 무효화·센서/입력/오디오/연결 정리·저장 자격 제거. 이전 계정 데이터·응답·대기 명령이 새 사용자에게 적용되지 않음 |
| 연결과 인증 | 유효 세션의 일시 네트워크 단절은 로그아웃과 구분하며 로컬 제스처·중지는 서버 응답 없이 동작. 인증 만료 후 필요한 검증을 건너뛰지 않음 |
| 비밀·실행 환경 | 비밀번호·재입력·토큰이 스냅샷·로그·Renderer 저장소·Media/Worker에 남지 않음. 운영 빌드에서 개발용 인증 대역이 선택되지 않음 |

### 서버 ERD 연동 검증

아래는 [#43](https://github.com/CCCR-TeamProj-01/Jarvis-client/issues/43)·최종 ERD 보완 [#47](https://github.com/CCCR-TeamProj-01/Jarvis-client/issues/47)의 목표 명세를 구현할 때 추가할 시나리오다. 이번 문서 갱신에서 실제 연동을 검증했다는 뜻은 아니다. 외부 앱 관측 등 확장 기능은 해당 범위를 구현할 때 적용한다.

| 시나리오 | 검증 기준과 원본 |
| --- | --- |
| 대화 생성 경쟁 | 동시 호출·생성 응답 유실/재전송에서 중복 대화 방지. 생성 실패·중지·로그아웃 뒤 늦은 ID로 입력/명령을 시작하지 않음([AI-04](../features/speech.md#대화-생성과-요청-완료)) |
| 음성 메시지 연계 | 한 발화의 업로드·STT·텍스트 처리가 같은 requestId에 연결되고 사용자 메시지를 중복 생성하지 않음. STT 실패는 본문 없이 추적하며 로컬 무음/취소 음성은 전송하지 않음([계약](../architecture/server-integration.md#대화메시지와-요청-식별)) |
| 응답과 실행 완료 | 실행 전 응답으로 성공/완료 처리하거나 도구 호스트를 닫지 않음. 여러 명령의 순서·중간 실패·취소·명령 없는 응답·TTS/후속 발화를 확정된 정책대로 처리([AI-02~04](../features/speech.md#대화-생성과-요청-완료)) |
| 결과 보고와 재실행 | 커밋 후 저장 확인, 저장 실패·확인 응답 유실 후 동일 시도 결과만 재전송, 같은 쌍의 다른 내용 거부를 검증. 재전송은 OS 실행 없이 한 결과로 수렴. 명시적 새 시도와 미보고·unknown·부작용 가능성을 구분([계약](../architecture/server-integration.md#명령-계획과-실행-결과)) |
| 도구·앱 식별 | 지원하지 않는 도구/버전, 잘못된 인자, 매핑 없는 앱 코드, 미설치·권한 철회를 실행 전 거절하고 원인을 보고([APP](../features/app-control.md#서버-도구와-앱-식별)) |
| 활동 동의·삭제 | 서버의 기본값·가입 안내와 설정 표시 일치, 허용된 설정 조합별 수집, 철회 직후 중단, 미확인 설정의 수집 금지, 계정 전환·삭제 후 대기 기록 재업로드 방지. 명령 결과 보고는 활동 동의와 분리([HIST](../features/activity-recommendation.md#수집-설정과-삭제)) |
| 활동 중복·출처 | 명령 결과와 OS 관측의 동일 활동 중복 방지, 반복 전송 event_key 유지, 외부 활동의 command_id 없음, 실제 실행/활성화와 출처 불명을 구분([활동](../features/activity-recommendation.md#명령-결과와-앱-활동)) |
| 추천 승인 | 표시만으로 명령 없음. 서버 만료 시각·PC별 대기 추천 제한을 적용. 승인 대기·실패·중복·만료·로그아웃 뒤 늦은 응답, 원래 요청 종료 후 승인, 여러 앱별 결과 처리. 독립 수신을 도입하면 요청 없는 추천에도 같은 검증 적용([REC](../features/activity-recommendation.md#추천-승인)) |
| 대화 데이터 | 확정한 본문 저장/삭제 정책과 사용자 안내 일치. 원시 음성·TTS·영상 영구 저장 없음, 운영 로그에 본문 없음. 서버 저장이 로컬 과거 대화 UI를 자동 활성화하지 않음([데이터](../architecture/data-security.md#대화와-일정-저장)) |
| 일정 저장·동기화 | 자체/Google 출처와 Google 읽기 전용 표시. 재가져오기 중복·회차별 변경/취소와 서버 조회/동기화 실패 구분. 종일 종료일 미포함·날짜 유지, 연결 해제 후 확정된 사본 처리와 늦은 응답 폐기([CAL](../features/calendar.md)) |

## 개발 전 결정 목록과 구현 순서

#### ERD 내부 불일치와 서버 확인 항목

절 번호는 사용자가 공유한 최종 ERD를 기준으로 한다. 아래 누락을 보완할 책임은 서버/API 계약에 있으며 클라이언트가 새 DB 필드나 상태 매핑을 임의로 확정하지 않는다.

| 항목 | 근거와 확인할 내용 | 클라이언트 기준 |
| --- | --- | --- |
| 결과 unknown 매핑 | 6-2절은 미도착 결과를 unknown으로, 7-2절은 outcome=unknown을 failed/error_code=unknown으로 매핑하고 observed+관측 unknown은 success로 표시. 서로 다른 미확인 상황의 최종 코드·조회 판정·보고 원본 저장 위치 확인 | 관측 수준·부작용 가능성을 보존하고 확인 불가를 자동 재실행하지 않음 |
| 수집 토글 조합 | 6-1절은 external ON에 자비스/외부 활동을 포함하지만 activity OFF에는 새 활동·추천 없음. 7-1절은 외부 수집에 두 토글 모두 ON을 요구. 자비스 OFF/외부 ON의 허용 여부·실제 의미 확인 | 허용 조합 확정 전 외부 수집을 임의 활성화하지 않음 |
| 활동 관측·정책 버전 | 7-1/7-4/7-5절은 observation_status·collection_revision·received_at 등을 사용하나 6-3절 APP_ACTIVITIES 상세에 해당 필드 없음. command 결과→활동 생성 시 정책 버전과 OS 관측의 중복 연결 방식도 확인 | 관측·동의 버전·event_key 계약을 유지하며 필드 축약으로 삭제하지 않음 |
| 본문 저장 | 6-6절은 비암호화·NULL 허용이나 2/8절에는 암호화, 대화 목록에는 복호화 표현이 남음. 본문 저장 동의 필드도 없음 | 상세 기준과 잔여 불일치를 안내하고 운영 본문 저장 완료로 간주하지 않음 |
| 추천 유효성·유일성 | 6-3절 규칙의 expires_at·suggested_at·active_slot·cooldown_until·근거/점수 등이 상세 테이블에서 빠짐. 단일 대기 추천·만료·승인 중복 방지를 실제 스키마/API에서 어떻게 보장할지 확인 | 서버 만료 검증·명시적 승인·중복 실행 방지 유지 |
| 요청·실행 식별과 제약 | 7-8절의 UK(user_id, request_id)가 메시지 상세에 없고 추천 승인 중복 생성 방지 제약도 불명확. 명령 인자·순서·실행 주체·기한도 명령 상세에 없음 | 요청·시도 멱등성과 Main의 실행 검증을 DB 테이블 축약으로 대체하지 않음 |
| 삭제·보관 참조 | 7-3/7-6절에 명령 created_at·device_app_id·target_alias, 대화 message_count·last_message_at 등 제거된 필드 참조가 남음. 7-7절 계정 삭제 순서에서 CALENDAR_EVENTS 누락 | 확정된 삭제 범위·기준 시각·저장 사본·서버 문맥·대기열 처리를 연동 전에 확인 |

최종 ERD는 `APP_ACTIVITIES`를 유지하고 사용자/기기 N:M 변경을 철회했다. `USER_DEVICES`·`user_device_id`를 새 계약에 도입하지 않는다. `AI_PRICE_RATES` 제거 등 서버 내부 테이블 변경은 클라이언트 기능 요구사항을 추가하지 않는다.

### 권장 구현 순서

기존 F-003~F-007은 핵심 공통 계약, F-008은 인증 계약 구현까지 완료했다. 다음 단계는 [개발 계획 #1](https://github.com/CCCR-TeamProj-01/Jarvis-client/issues/1)과 [인증 기능 #5](https://github.com/CCCR-TeamProj-01/Jarvis-client/issues/5)를 기준으로 진행한다. 각 단계는 검증 가능한 구현 단위로 이슈·PR을 나누며 문서 작업만으로 `feature_list.json`에 새 항목을 만들지 않는다.

1. 완료(F-008): 인증 데이터·공개 API·Main 포트, 요청 세대 비교·미인증 화면 스냅샷 검증을 구현했다. 실제 인증·기능 차단·서버/저장소 대역의 동작은 2~3단계에서 연결한다.
2. 완료(F-009): 앱 생명주기·트레이·단축키·창 관리와 UI IPC·기본 상태를 구현했다. 시작 시 인증 화면을 우선하고 미로그인 호출은 로그인으로 안내하며 주요 기능을 시작하지 않는다. 중지·종료 경로는 인증 없이 유지한다. 실제 인증 입력/제출·복구는 3단계에서 연결한다.
3. 완료(F-012): 로그인·회원가입·중복 확인 화면과 AuthManager·보호 저장소·로그인 유지·로그아웃·만료 처리를 개발용 인증 서버 대역에 연결한다. 실제 서버 없이 로그인 확인·재시작 복구·실패·지연·계정 전환과 모든 진입점의 접근 제한을 검증한다.
4. 완료(F-013, 장치 설정 저장 제외): Media Renderer와 SensorManager의 장치·권한·사용권과 카메라·마이크 열기·닫기를 구현했다. 영상 프레임·PCM 수집은 5~6단계에서 더한다. F-023에서 설치 식별자·Main 기기 설정 저장과 음성 출력 설정 소비를 구현했다. 설정 편집 UI·장치/단축키 설정 적용은 후속이다. 원래 범위: 인증 후에만 센서를 시작하며 로그아웃·권한 철회·중지에서 정리한다.
5. 일부 완료(F-014): CapabilityRegistry·ToolExecutor와 macOS 앱 어댑터(목록·실행·전환·복귀·URL)를 구현했다. 이어서 F-018에서 카메라 프레임 → 손 추적 Worker → 손 관측 파이프라인과 `HandTrackingService`를 구현했다. 이어서 F-019에서 GestureController(좌표 보정·평활·Pinch 클릭·손실 복구)와 libnut 기반 OS 포인터 어댑터, 시작·종료 진입점을 구현했다. 남은 범위: 최근 작업 전환(GEST-04), Windows 앱 어댑터, 실기기 Pinch·평활 임계값 조정. 원래 범위: OS 앱·입력 어댑터와 CapabilityRegistry·ToolExecutor, 손 추적 Worker·GestureController를 구현한다. 두 OS에서 실제 커서·클릭·전환·로컬 중지와 백그라운드 미디어를 작게 검증한다. 모션 Worker는 공통 진입점 담당을 조율해 독립 구현할 수 있다.
6. 일부 완료(F-015): PCM 수집·순환 버퍼, 호출 후 Silero VAD(별도 프로세스), 완료 발화 추출을 구현했다. 호출어 엔진은 한국어 모델이 없어 보류했다. 이어서 F-016·F-017에서 대화(`ConversationManager`)와 음성 세션의 분리, 음성 세션 상태 전이, 서버 대역, 오디오 재생, 텍스트 입력 경로를 구현했다. 이어서 F-020에서 어시스턴트의 도구 호출을 검증·실행하고 결과를 대화에 보여 주는 클라이언트 연결부를 구현했다(개발용 대역으로 검증). 남은 범위: 호출어 엔진, 서버 계약 확정 후 실제 연동(서버 메시지 매핑). 원래 범위: PCM·Ring Buffer → 교체 가능한 KWS → SpeechSessionController → 호출 후 VAD → 완료 발화와 오디오 재생을 구현한다. 서버 대역으로 연속·후속 발화·무음·재생 중 입력 억제·중지·인증 무효화·늦은 결과를 검증한다.
7. 사용자별 실행 기록·삭제·전송 대기열과 결과·확인·추천·캘린더 화면을 개발용 데이터에 연결한다. 계정 격리와 정상·실패·취소·만료 흐름을 통합 검증한다.
8. 실제 서버는 인증·가입·중복 확인·세션 복구·설치 식별/기기 등록부터 연동한다. 이어서 서버 대화 생성·메시지/요청 매핑·실행 전 응답/명령 계획·시도별 결과 보고, 완료 발화의 서버 STT·TTS, 캘린더·추천·기록 동기화를 순차 연결한다. 각 연결 전 위 결정 목록의 관련 정책을 양쪽에서 합의하고 현재 대역 포트를 확장한다.
9. 각 단계에서 Windows·macOS와 설치 패키지 검증을 수행하고, 마지막에 삭제·취소·단절·인증 만료·권한 철회·성능의 전체 완료 시나리오를 확인한다.
