# 서버 연동과 실행 계약

서버 역할, WSS 필드, 취소·만료·중복 실행 규칙의 원본 문서다.

2026-10-21 서버 ERD 수정 방향([#43](https://github.com/CCCR-TeamProj-01/Jarvis-client/issues/43))과 최종 ERD([#47](https://github.com/CCCR-TeamProj-01/Jarvis-client/issues/47))를 반영한 목표 계약이다. 실제 HTTPS/WSS 어댑터는 미구현이며 아래 의미 계약이 엔드포인트·JSON 스키마의 확정을 뜻하지 않는다. 미확정 정책과 ERD 내부 불일치는 [결정 목록](../delivery/validation.md#서버-erd-반영-후-결정-목록)에서 관리한다.

## 서버 모듈

| 모듈 | 주요 책임 |
| --- | --- |
| AuthAndDevice | 아이디·비밀번호 가입·로그인·중복 확인, 세션 검증·갱신·폐기, 기기 소유권, 연결 세션, 대상 기기 명시 |
| RequestOrchestrator | 요청 상태·취소·기한·추가 질문·결과 응답 조정 |
| SpeechService | 완료 발화의 STT, 확정된 응답의 TTS, 음성 요청 취소·기한·오류 처리 |
| Agent | 의도 해석, 가용 도구 선택, 구조화된 인자 생성 |
| ClientToolGateway | 기기별 기능 확인, 실행 요청 전달, 결과 상관관계 관리 |
| Calendar | 자체 일정과 Google 일정의 저장·기간 조회·동기화, 외부 계정 연결·토큰 갱신·해제 |
| Activity | 실행 이력 수집·조회·삭제, 이벤트 중복 제거 |
| Recommendation | 연관도 계산·노출 판단·승인 상태·효과 집계 |
| Operations | 오류·응답 시간·사용량, 운영 화면용 집계 |

서버 구현 언어와 프레임워크는 미확정이다. HTTP API·WSS·모듈 경계를 먼저 고정하고 언어 선택과 분리한다. MySQL을 주 저장소로 사용하며, 초기 MVP에서 별도 메시지 브로커나 벡터 DB를 필수로 두지 않는다.

## 계정 인증 계약

제품 동작·입력 규칙과 설치 식별자의 수명은 [AUTH-01~07](../features/auth.md)을 따른다. 아래는 최종 ERD 3절·6-1절에 따라 Main의 인증 어댑터가 서버와 주고받을 연산의 의미다.

| 연산 | 필수 계약 |
| --- | --- |
| 아이디 중복 확인 | `loginId`에 대한 사용 가능·중복·유효하지 않은 입력·실패 구분. 가입 시 최종 유일성 검사를 대체하지 않음 |
| 회원가입 | `loginId`·`password`를 입력으로 받고 가입 성공·아이디 중복·입력 오류·실패를 구분. 서버에서 같은 정규화 규칙과 저장소 제약으로 동시 가입의 중복 방지. 재입력 값이나 클라이언트의 사용 가능 플래그는 신뢰 근거가 아님 |
| 로그인·기기 등록 | 자격 증명과 Main의 설치 식별자 `device_key`·기기 이름·OS·클라이언트 버전을 함께 전달. 서버가 `(user_id, device_key)`로 기기를 찾거나 만들고 `AUTH_SESSIONS.device_id`에 연결한 뒤 공개 사용자·기기 정보와 Main 내부 인증 자격 증명 반환. 반복 로그인은 같은 계정의 같은 기기로 수렴. 잘못된 인증 정보·일시 제한·서버 오류·통신 실패를 구분 |
| 세션 검증·갱신 | 보호 저장된 자격 증명의 현재 유효성과 사용자·기기 연결을 확인하고 필요 시 새 토큰 쌍으로 갱신. 무효·만료·폐기와 일시 통신 실패 구분. 교체한 자격 증명은 보호 저장소에도 반영 |
| 로그아웃 | 현재 로그인 세션의 폐기. 다른 PC 세션의 일괄 폐기를 의미하지 않음. 반복 요청에 안전하게 처리하며 클라이언트의 즉시 기능 차단·로컬 정리를 지연시키지 않음 |

접근 토큰은 발급 후 1시간, 갱신 토큰은 발급·갱신 후 30일 동안 유효하다. 갱신은 새 토큰 쌍을 발급하며 이전 갱신 토큰은 즉시 무효가 된다. 교체된 갱신 토큰이 다시 사용되면 서버가 해당 세션을 폐기한다. Main은 같은 세션의 갱신을 직렬화하고 교체 전 토큰을 자동 재사용하지 않는다. 응답 유실·보호 저장 실패 시의 복구 절차는 API 합의 전까지 임의로 정하지 않는다.

서버는 비밀번호를 해시로 저장하고 로그인·가입 입력을 다시 검증한다. 비밀번호·토큰은 요청·오류 로그에 기록하지 않는다. HTTP API와 WSS 모두 토큰에서 사용자·기기·세션을 확인하며 매 요청 본문에 `userId`·`deviceId`를 중복 요구하지 않는다. 클라이언트가 보낸 식별자만으로 소유권을 인정하지 않는다.

로그아웃·사용자 전환 이후 이전 세션의 WSS·음성·캘린더·추천 응답은 적용하지 않는다. 재연결은 현재 인증 세대에만 연결하며, 기록 대기열도 인증된 같은 사용자의 데이터만 정책 검증 후 전송한다. 가입·로그인·중복 확인과 세션 복구 자체는 미로그인 상태에서도 호출 가능한 인증 전용 연산이다.

## 대화·메시지와 요청 식별

서버에서 `USER_REQUESTS`의 요청 메타데이터를 `CONVERSATION_MESSAGES`로 통합해도 클라이언트의 요청 단위는 유지한다. DB 행과 클라이언트 내부 상태를 같은 구조로 만들지 않는다. 메시지 본문의 저장·보관은 [데이터와 보안](data-security.md#대화와-일정-저장)을 따른다.

| 식별자 | 의미와 연결 |
| --- | --- |
| `conversation_id` / 내부 `conversationId` | 서버에 생성한 활성 대화의 외부 식별자. DB 내부 `conversation_pk`는 클라이언트에 필요하지 않음 |
| `request_id` / 내부 `requestId` | 클라이언트가 입력 처리 전에 생성하는 한 요청의 식별자. 음성 인식·응답·취소·명령을 연결하며 DB 메시지 ID 발급 전에도 존재 |
| `message_id`, `source_message_id` | 서버가 저장한 메시지와 명령의 원인 메시지. 한 사용자 메시지에 여러 명령 연결 가능. 전송 이벤트의 `messageId`와 구분 |
| `command_id` | 서버가 생성한 명령. 사용자 메시지 또는 승인된 추천과 연결. 재시도해도 같은 명령 |
| 내부 `executionId`, 외부 `command_id` + `attempt_no` | 명령의 실행 시도. Main의 안정적인 실행 ID를 외부 명령·시도 쌍에 매핑하고 재전송 동안 유지. 별도 `executionId` wire 필드의 필요 여부는 API 합의 사항이며 결과 행의 `result_id`와 구분 |
| `recommendation_id` | 승인·거절·닫기·만료와 승인으로 생성된 명령의 상관관계 |
| `event_key` | 앱 활동 한 건의 안정적인 이벤트 ID. 실행 시도와 별개이며 수집·전송 중복 제거에 사용 |

Main은 활성 대화가 없으면 인증된 현재 기기로 서버 대화를 생성한 뒤 입력을 제출한다. 서버의 생성 응답은 호출 당시 인증·로컬 대화 세대가 유효할 때만 적용한다. 생성 요청의 재전송은 같은 생성 식별자로 중복을 막으며 생성 실패·취소로 명령을 실행하지 않는다. 생성 기한과 재시도 프로토콜은 API 합의 항목이다. 현재 로컬 ID 생성 구현과의 차이는 [AI-04](../features/speech.md#대화-생성과-요청-완료)에 둔다.

최종 ERD 6-6절의 서버 문맥 기준은 메모리 보관 30분, 문맥이 없을 때 해당 대화의 최근 메시지 20개를 `message_id` 순서로 복구하는 방식이다. 앞부분이 잘려 호출과 짝이 맞지 않는 도구 결과는 제외한다. 서버 문맥 보관은 로컬 대화·음성 세션의 수명과 별개이며 끝낸 대화 ID를 다시 사용하지 않는다. 본문 미보관·삭제 후 복구 범위는 데이터 정책과 함께 합의한다.

사용자 입력은 `role=user`, `message_type=request`와 입력 방식으로 연결한다. 서버가 수신한 음성의 STT가 실패해도 같은 `request_id`의 오류를 추적하고 본문 없는 메시지를 허용한다. 클라이언트에서 업로드 전에 끝난 무음·취소 구간은 이 기록을 만들기 위해 전송하지 않는다. 서버가 원래 음성을 이미 받았다면 클라이언트의 후속 텍스트 제출을 두 번째 사용자 요청으로 저장하지 않도록 같은 요청 ID로 연결한다.

`input_method=gesture/ui`는 서버 요청을 만드는 명시적 동작을 표현할 수 있다. 커서 좌표·매 프레임·클릭·센서 중지 전체를 대화 메시지로 전환하거나 서버 처리에 종속시키지 않는다. 메시지 없는 명령을 지원한다면 대상 사용자·기기·요청 수명과 허용 진입점을 별도로 검증해야 하며 `source_message_id=NULL`만으로 자동 실행을 허용하지 않는다.

## 명령 계획과 실행 결과

서버는 사용자 요청에 연결된 명령을 만들고 실행 전 안내·구조화된 명령 목록·추천 정보를 반환할 수 있다. 클라이언트는 응답 문장에서 명령을 추출하지 않는다. 실행 전 응답을 표시한 시점과 요청 완료를 구분하는 제품 동작은 [AI-02~04](../features/speech.md#대화-생성과-요청-완료)를 따른다.

- 명령에는 명령·시도·상위 요청 식별, 실행 대상, 도구명·버전·인자, 순서, 발행·만료 시각과 필요한 가용 상태 리비전을 연결한다. `requested_app_code`만으로 URL·복귀 등 모든 도구의 인자를 대체하지 않는다.
- 서버는 AI에 제공할 도구 정의와 계획을 관리한다. 클라이언트는 지원 도구·버전·권한·현재 가용 상태를 보고하고 실행 직전에 다시 검사한다. 서버 공통 앱 코드와 로컬 OS 앱 ID의 매핑은 [앱 제어](../features/app-control.md#서버-도구와-앱-식별)를 따른다.
- 클라이언트 대상 명령만 Main의 실행기로 보낸다. 서버·외부 서비스 도구의 실행은 서버가 담당한다. 기본 대상은 요청이 들어온 현재 기기이며 다른 PC 원격 실행을 추가하지 않는다.
- 같은 요청의 부작용 명령은 지정 순서로 처리한다. 중간 실패 시 후속 명령을 계속할지·의존 명령만 중단할지와 실행 전 안내의 TTS 순서는 API 연동 전에 결정한다. 순서만으로 의존 관계를 추정하지 않는다.
- 추천 정보는 실행 명령이 아니다. [추천 승인](../features/activity-recommendation.md#추천-승인) 이후 서버가 생성한 명령을 실행한다.

`COMMAND_REQUESTS`는 명령 정보를, `COMMAND_RESULTS`는 실행 시도별 결과를 받는다. 기존 로컬 `ToolExecutionReport`와 다음 외부 보고의 변환은 Main의 서버 어댑터가 담당한다.

| 결과 정보 | 보고 규칙 |
| --- | --- |
| 명령·실행 시도 | `command_id`·`attempt_no`로 보고 시도를 식별하고 Main 내부 `executionId`와 매핑. `request_id` 및 원인 메시지와 상관관계를 유지 |
| 결과·관측 | 실행 전 미시작, 관측됨, 실패, 확인 불가를 구분. `confirmed`·`dispatched`·`unknown`과 실패의 부작용 가능성을 보존. 서버의 success/failed/unknown 등에 매핑할 때 정보를 잃지 않음 |
| 취소·만료 | 취소 요청과 실제 실행 여부를 분리. 이미 일어난 OS 동작의 결과를 취소 성공으로 덮어쓰지 않음 |
| 오류 | 기계 판정은 `error_code`·`failure_stage` 사용. `result_message`는 사용자 안내용으로 제한하며 스택·토큰·임의 서버/OS 오류 원문을 넣지 않음 |
| 시각 | 클라이언트의 시작·종료 시각과 서버 수신 시각 `reported_at` 구분. 시간 형식은 [시각 계약](#시각-계약) 참조 |

같은 결과를 재전송할 때는 같은 시도 ID·순번·내용을 사용하고 서버는 `UNIQUE(command_id, attempt_no)`에 해당하는 한 시도로 처리한다. 같은 쌍의 내용이 다르면 서버가 거부한다. 실제 재실행은 명시적인 새 시도로 구분하며 순번 발급 주체는 API 합의로 고정한다. DB의 중복 결과 제약은 OS 중복 실행 방지를 대체하지 않는다. 미보고 상태는 보고 기한·조회 결과에 따라 `unknown`으로 판정하며 단순 통신 실패를 실행 실패로 확정하지 않는다. `unknown`이나 부작용 가능성이 있는 실패는 자동 재실행하지 않는다. ERD의 결과 테이블과 7-2절의 상태 매핑 불일치는 [서버 확인 항목](../delivery/validation.md#서버-erd-반영-후-결정-목록)으로 남긴다.

서버는 결과와 관련 레코드를 커밋한 뒤 저장 확인을 보낸다(최종 ERD 7-8절). 저장 실패나 확인 응답 유실 시 클라이언트는 같은 `command_id`·`attempt_no`의 결과만 재전송하며 OS 명령을 다시 실행하지 않는다. 저장 확인은 결과 보고 완료를 뜻하며 OS 실행 성공과는 별개다. 인증된 동일 사용자·기기·시도에만 보고하며 로그아웃 이후 늦은 보고가 현재 UI나 실행을 되살리지 않는다. 확인 응답의 wire 형식·대기열 영속성·재시도 기한은 API 구현 전에 합의한다. 동의 기반 앱 활동 대기열과 명령 결과 보고를 혼합하지 않는다.

## 음성 데이터 계약

MVP 기본안은 로컬 VAD가 확정한 한 발화를 인증된 HTTPS 요청으로 업로드하고, 도구 요청·결과와 대화 상태는 기존 WSS로 교환하는 방식이다. 서버 STT 결과의 텍스트와 최종 응답의 TTS 오디오는 같은 대화·요청 ID에 연결한다. 클라이언트는 인식 요청과 응답 요청을 별도 단계로 다루며(실제 전송에서 한 번의 교환일 수 있음) 둘에 같은 `conversationId`·`requestId`를 붙인다. 글로 입력한 내용은 업로드 없이 텍스트로 응답 요청에 담기며, 서버 입장에서 입력 방식은 응답 처리에 영향을 주지 않는다. TTS 오디오의 실제 전달 방식과 엔드포인트는 서버 구현 시 확정하되, 오디오 바이트를 JSON 로그나 도구 인자에 넣지 않는다. 실시간 오디오 스트리밍은 MVP 범위 밖이다.

| 데이터 | 필수 계약 |
| --- | --- |
| 발화 업로드 | 인증된 사용자·기기, `protocolVersion`, `conversationId`, `requestId`, `speechSessionId`, 상태 버전, 오디오 형식·샘플레이트·채널·길이, 완료 발화 바이트. 최대 길이·크기와 형식 불일치를 검증 |
| STT 결과 | 같은 요청·세션 식별자, 인식 텍스트 또는 빈 결과·오류, 처리 상태. 서버는 빈 결과로 도구를 실행하지 않음 |
| TTS 결과 | 같은 요청·세션 식별자, 실행 전 안내인지 확인된 결과 안내인지 구분 가능한 텍스트, 재생 가능한 오디오 형식·길이·바이트 또는 생성 오류. 오디오 오류 시 텍스트 결과 제공. 재생 시점은 AI-02~04의 요청 수명과 연결 |
| 취소 | 음성 업로드·STT·TTS의 취소 요청을 연결. 이미 시작된 서버 연산의 즉시 중단은 보장하지 않고 클라이언트는 늦은 결과를 폐기 |

대기 중 마이크 스트림과 VAD가 완료하지 않은 구간은 전송하지 않는다. 음성 바이트는 오프라인 대기열이나 재연결 자동 재전송 대상에 넣지 않는다. 클라이언트와 서버는 허용 오디오 형식·최대 길이·최대 바이트·요청 기한을 구현 전에 함께 확정한다. 원시 음성의 보관 경계는 [데이터와 보안](data-security.md)을 따른다.

## WSS 메시지 계약

| 필드 | 목적 |
| --- | --- |
| protocolVersion, messageType, messageId | 버전 호환, 메시지 종류, 이벤트 중복 식별 |
| 인증된 사용자·기기, connectionSessionId | 현재 세션에서 소유권·대상 기기를 확인. 토큰으로 결정되는 userId·deviceId를 모든 요청 본문에 중복 요구하지 않으며, 포함된 값은 인증 정보와 대조 |
| conversationId, requestId, 원인 메시지 ID, commandId, executionId, attemptNo | 대화·상위 요청·저장 메시지·명령·실행 시도의 상관관계. 실제 wire 필드명과 필수 여부는 메시지 종류별 스키마에서 확정 |
| toolName, toolVersion, arguments | 등록 도구와 검증할 입력 |
| issuedAt, expiresAt | 기한 판단. 서버 시간과 로컬 단조 시계 기반 경과 시간을 함께 고려 |
| capabilityRevision | 오래된 가용 상태에 근거한 요청 식별 |

WSS의 제어 메시지는 음성 업로드·STT 결과·TTS 결과의 `requestId`와 연결한다. 바이너리 오디오를 전달하는 방식이 바뀌어도 도구 실행의 `executionId` 계약은 유지한다.

위 표는 논리 필드다. `messageType`은 전송 이벤트 종류이며 DB 메시지의 `message_type=request/response/interaction`과 별개다. 전송 이벤트 `messageId`와 DB `message_id`도 별도 이름으로 매핑한다. DB BIGINT 식별자는 JavaScript 정수 정밀도를 잃지 않는 불투명 문자열로 전달하는 것을 계약 기준으로 삼는다. ERD 변경만으로 HTTPS/WSS 전송 방식을 바꾸지는 않는다.

앱 실행 등 부작용 도구는 `executionId`를 기준으로 중복 실행을 방지한다. 전송 계층만으로 exactly-once 실행을 보장한다고 가정하지 않는다. 실행 도중 연결이 끊겨 결과를 알 수 없으면 미확인 상태로 남기고, 재연결 시 조회·정합성 확인을 먼저 한다. 만료된 실행 요청은 다시 보내지 않는다.

## 시각 계약

서버 저장 시각은 UTC `DATETIME(6)`이며 API는 UTC임이 명시된 ISO 8601 문자열 등 시간대가 모호하지 않은 형식을 사용한다. 정밀도·직렬화 형식은 wire 스키마에서 확정한다. 화면의 날짜·시각과 기간 조회 경계는 계정의 `USER_SETTINGS.timezone`을 기준으로 변환하고, 종일 일정은 [캘린더](../features/calendar.md)의 날짜 의미를 유지한다. 실행 기한·지연 측정은 로컬 단조 시계를 사용하며 DB 시각 정밀도를 로컬 타이머에 강제하지 않는다.

## 취소와 오류 규칙

- 실행 대기 중인 요청은 취소·만료 시 시작하지 않는다. 실행 직전에 로컬에서 한 번 더 검사한다.
- 로그아웃·인증 무효화 시 새 도구·음성 요청을 차단하고 현재 인증 세대의 연결·진행 작업을 정리한다. 상세 화면·상태 전이는 [계정 인증](../features/auth.md#인증-상태와-시작-흐름)을 따른다.
- 이미 시작된 OS 동작은 취소가 되돌림을 보장하지 않는다. 실행 여부와 취소 처리 여부를 분리해 안내한다.
- 카메라·마이크·접근성 권한 철회 시 해당 기능을 중단하고 가용 상태를 갱신한다. 마이크 철회·중지 시 SpeechSessionController는 KWS/VAD·음성 업로드·TTS 재생을 중단하고 원시 오디오·대기 발화를 폐기하며 지연된 서버 응답을 거부한다.
- 네트워크 단절·STT 실패 시 완료 발화를 오프라인 대기열에 보관하거나 자동 재전송하지 않는다. TTS 실패 시 확인된 텍스트 결과를 표시한다.
- 로컬 인식이나 네트워크 오류가 있어도 단축키·트레이에서 중지·종료 경로를 사용할 수 있어야 한다. 설정은 인증 정책에 따라 로그인 이후에 제공한다.
- 상태 오버레이가 표시된 순간과 사용자 입력 창을 직접 연 순간을 구분해 포커스 정책을 적용한다.
