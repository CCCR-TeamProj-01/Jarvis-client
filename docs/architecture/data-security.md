기록 삭제 이후 오프라인 기기가 이전 대기 기록을 다시 올리지 않도록 삭제 기준 시각·범위와 수집 정책 버전을 동기화한다. 명령 결과 보고와 동의 기반 앱 활동의 구분은 [실행 이력](../features/activity-recommendation.md#명령-결과와-앱-활동)을 따른다.

서버 STT 사용 시 완료 발화가 기기 밖으로 전송된다는 점을 사용자 설정과 권한 안내에 명확히 표시한다. 음성 바이트·인식 텍스트·입력한 글·TTS 오디오는 운영 로그와 오류 보고에 포함하지 않는다. 서버가 외부 음성 제공자를 사용하게 되면 전송 대상·지역·보관 정책을 별도로 결정하고 사용자 안내에 반영한다.

### 대화와 일정 저장

서버 대화/메시지 저장을 문맥 처리 흐름에 포함한다. 요청 식별·입력 방식·처리 상태·STT 오류 등 최소 메타데이터와 사용자 입력·인식 텍스트·AI 답변·도구 결과 본문을 구분한다. STT 실패·본문 미보관 메시지의 본문은 NULL일 수 있다. 본문이 없다는 이유로 요청 처리 사실이나 실패 상태를 누락하지 않는다.

최초 ERD와 수정안에서 다른 대화 본문 암호화·보관 기간·저장 선택 정책은 [결정 목록](../delivery/validation.md#서버-erd-반영-후-결정-목록)에서 합의한다. 정책 확정 전에는 운영용 본문 저장을 완료 기능으로 취급하지 않는다. 본문을 저장한다면 안내·조회 권한·삭제 범위와 서버 문맥의 삭제/재구성까지 일치시켜야 한다. 사용자 대화 저장이 운영 로그의 본문 수집 허용을 의미하지 않는다.

현재 클라이언트 화면의 대화는 메모리에만 있으며 로컬 대화 영구 저장·과거 대화 목록/재개 UI는 별도 범위다. 서버 메시지 저장을 위해 원시 음성·영상·TTS 오디오를 영구 저장하거나 오프라인 재전송하지 않는다.

일정은 서버가 자체 일정과 Google 일정 사본을 저장하는 방향으로 변경한다. Google 연결 해제 시 자격 증명과 가져온 일정 사본의 삭제 여부는 별도 정책이며 자체 일정까지 묶어 지우지 않는다. 정책·클라이언트 안내는 [캘린더 원본](../features/calendar.md#저장연결-해제와-범위)에 연결한다. 서버 저장소 도입만으로 로컬 일정 DB나 할 일 UI를 추가하지 않는다.

### 설정의 소유 범위

계정 시간대·앱 활동 수집 동의는 서버 계정 설정을 원본으로 삼고 Main이 현재 사용자에게 적용한다. 마이크·카메라 장치 선택, 호출·제스처·단축키 등 PC 설정은 로컬에서 관리한다. 계정 설정 반영값과 전송 대기열은 사용자별로 격리하며 설치 식별자와 혼합하지 않는다. 수집 설정의 의미·철회·삭제는 [수집 설정](../features/activity-recommendation.md#수집-설정과-삭제)을 따른다.

### 기기 로컬 저장 형식

F-023([#45](https://github.com/CCCR-TeamProj-01/Jarvis-client/issues/45))에서 Main 전용 `settings/` 저장 계층을 구현한다. 저장 위치는 Electron `userData`이며 다음 두 문서를 인증 저장소 `auth-credential.bin`과 분리한다.

| 파일 | 버전 1 내용 | 수명 |
| --- | --- | --- |
| `installation.json` | `version: 1`, UUID `deviceKey` | 설치 단위. 로그아웃·계정 전환·기기 설정 초기화 후에도 유지 |
| `device-settings.json` | `version: 1`, `settings.speechOutputEnabled`(boolean, 기본 true) | PC의 음성 응답 재생 설정. 원본 계정 설정과 인증 비밀은 허용하지 않음 |

`LocalStatePort`는 초기화·복사된 스냅샷 조회·전체 설정 검증/저장·기기 설정 초기화만 Main에 제공한다. 초기 필드는 기존 음성 응답 재생에 사용하고, 설정 편집 UI·입력 장치/단축키 재설정은 후속 작업이다. 서버 요청의 설정이나 DB 기기 등록 성공을 의미하지 않는다.

문서가 없는 새 설치에만 설치 키를 생성한다. 설정은 남아 있는데 설치 문서만 없다면 데이터 유실로 처리해 새 키를 발급하지 않는다. 유효한 설치 키만 있고 설정이 없으면 기본 설정을 생성한다. 기존 문서의 손상·알 수 없는 필드·잘못된 타입은 읽기 실패이며 기본값으로 덮어쓰지 않는다. 첫 버전에는 이전 형식이 없으므로 자동 마이그레이션을 제공하지 않고, 다른 버전은 미지원 오류로 보존한다. 복구는 앱을 종료한 뒤 원본을 보관하고 해당 파일을 수동 복구하는 방식이며, 지원하지 않는 버전의 설정 초기화로 새 형식을 덮어쓰지 않는다.

설치 키와 설정을 모두 읽고 검증한 뒤 초기화 성공을 게시하고, 설정 갱신은 디스크 저장이 성공한 뒤 메모리에 반영한다. 동일 앱의 갱신은 순차 처리한다. 완성된 임시 파일을 게시해 부분 저장을 방지하고 설치 키 최초 생성은 기존 파일을 덮어쓰지 않는 방식으로 경쟁을 처리한다. 저장 실패 후 임시 키로 성공 처리하지 않는다. 동작 검증과 완료 상태는 구현 현황·진행 로그에 남긴다.

### 인증 정보와 계정 격리

기능·화면 정책은 [계정 인증](../features/auth.md)을 따른다. 인증 저장소는 Main 내부 `CredentialStorePort` 뒤에 두며 Electron `safeStorage` 등 OS 보호 수단의 가용성을 확인한다. 보호 저장이 불가능하거나 실패하면 로그인 유지 불가를 알리고 평문으로 대체하지 않는다. 현재 실행의 로그인 성공과 재실행 복구를 위한 저장 성공은 별도로 확인한다.

비밀번호·재입력은 폼 처리에 필요한 동안만 보유하고 전역 UI 상태·localStorage·설정 파일·대기열·로그·오류 보고에 넣지 않는다. 재입력은 UI에서만 검증하고 Main과 서버로 보내지 않는다. Main은 비밀번호를 HTTPS 인증 요청에만 사용하고, 세션 비밀을 `AuthSnapshot`·일반 상태 이벤트·Media API·Worker에 전달하지 않는다. Renderer가 서버 인증을 우회하거나 토큰을 직접 저장·갱신하지 않는다.

서버는 비밀번호를 복호화 가능한 값으로 저장하지 않고 비밀번호 전용 해시를 사용한다. 해시 알고리즘·파라미터·자격 증명 수명은 서버 구현 단계에서 확정한다. 로컬 로그인 유지에는 비밀번호 대신 서버가 발급한 세션 복구용 자격 증명을 사용한다.

기록·삭제 요청·캘린더·추천과 전송 대기열은 서버의 `userId`를 소유자로 구분한다. 로그아웃·계정 전환 시 UI 구독과 계정 데이터를 분리하며 이전 사용자의 대기 데이터를 새 인증으로 전송하지 않는다. 이전 계정 데이터의 보관·삭제는 수집·삭제 정책에 따르며 다른 사용자에게 노출하지 않는다. 인증 세대가 바뀐 요청·응답·명령은 폐기한다.

참고: [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage), [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

### 로컬 오디오 처리 경계

수집한 PCM은 Media Renderer의 30초 순환 버퍼와 Main의 처리 중 메모리에만 있다. 듣는 쪽이 없으면 Main은 PCM을 버리고 어디에도 저장하지 않는다. 발화 하나를 받으면 VAD를 멈추고 버퍼를 비운 뒤 마이크 사용권을 반납하며, 완료된 발화 바이트만 호출한 쪽에 남는다. 오디오는 로그·진단 출력에 넣지 않는다(셀프테스트도 길이와 크기만 출력한다).

### 카메라·마이크 권한 경계

Electron session의 권한 처리기는 기본 거부다. 카메라·마이크는 비표시 Media Renderer가 Main이 센서를 시작하는 중이거나 사용 중인 종류에 대해서만 허용하며, UI 창·다른 문서·그 밖의 모든 권한 요청은 거부한다. Chromium의 가짜 UI 승인 스위치는 처리기를 우회하므로 개발용 가짜 장치에서도 쓰지 않는다. macOS 사용 목적 문구는 패키징 설정에 둔다.

### 실행과 UI 경계

Renderer는 `contextIsolation`과 제한된 `contextBridge` API를 사용하고 Node.js 직접 접근을 허용하지 않는 구성을 기본으로 한다. Main은 IPC 발신 창·인자·기능 범위를 검증한다. 외부 콘텐츠나 LLM 출력은 실행 권한이 되지 않으며, 등록 도구·허용된 앱·검증된 URL 범위 안에서만 실행한다.

미로그인·인증 확인 중에는 화면 숨김만으로 접근을 제한하지 않고 Main이 현재 인증을 검사한다. 인증 전용 연산과 중지·정리·종료를 제외한 주요 기능의 IPC·트레이·단축키·OS 실행을 차단한다.
