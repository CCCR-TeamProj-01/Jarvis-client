# 제품 범위와 공통 요구사항

통합 명세 v0.2의 1장과 BASE·OPS·LIFE 요구사항을 바탕으로 분리하고 현재 설계 변경을 반영했다. 세부 기능의 원본은 각 기능 문서다.

자비스는 Windows와 macOS에서 백그라운드로 동작하는 AI 개인 비서다. 음성·제스처·단축키로 호출하고, 작은 오버레이와 필요한 순간에만 표시되는 창으로 상호작용한다. Electron 클라이언트가 센서 입력·로컬 호출어 및 발화 구간 감지·PC 제어를 담당하며, 서버는 STT·TTS·자연어 요청 해석·외부 서비스 연동·기록 기반 추천을 담당한다.

표의 ID는 이 초안에서 사용할 요구사항 식별자다. MVP는 완료 필수 기능, 확장은 후속 개발 기능이다.

2026-10-21 서버 ERD 수정 방향([#43](https://github.com/CCCR-TeamProj-01/Jarvis-client/issues/43))과 최종 ERD([#47](https://github.com/CCCR-TeamProj-01/Jarvis-client/issues/47))를 반영했다. 기기 N:M 매핑 변경은 철회되어 계정별 기기 연결을 유지하며 앱 활동과 명령 결과를 분리한다. 최종 ERD 11절의 P0/P1 표기·확장 도구 목록은 이 문서의 클라이언트 MVP와 일치하지 않는 부분이 있다. 서버 테이블의 추가·통합만으로 구현 완료·MVP 승격·지원 도구 확대를 선언하지 않으며, 변경할 범위는 요구사항·완료 조건으로 별도 합의한다. 미확정 정책은 [결정 목록](../delivery/validation.md#서버-erd-반영-후-결정-목록)에 둔다.

## MVP 범위

| 영역 | MVP 포함 범위 |
| --- | --- |
| 계정 | 아이디·비밀번호 로그인, 아이디 중복 확인·비밀번호 재입력을 포함한 회원가입, 로그인 유지·로그아웃·주요 기능 접근 제한, 설치 식별자와 계정별 기기 등록 |
| 호출 | 한국어 Wake Word, 제스처, 글로벌 단축키, 시스템 트레이 |
| 인터페이스 | 포커스를 빼앗지 않는 상태 오버레이, 임시 입력·결과·확인 창, 설정 |
| 음성 | 공통 PCM 입력·순환 버퍼, 대기 중 로컬 호출어 감지, 호출 후 로컬 VAD, 완료 발화의 서버 STT·서버 의도 분석·서버 TTS 오디오 재생 |
| 대화 | 서버 대화 생성·메시지/요청 연결·문맥 활용, 실행 전 응답과 명령별 실제 결과 구분. 본문 보관 정책과 과거 대화 UI 범위는 별도 결정 |
| 앱 제어 | 앱 식별·상태 조회, 실행·전환, 호출 전 작업 복귀, 기본 브라우저 URL 열기 |
| 제스처 제어 | 명시적 시작·종료, 검지 커서 이동, Pinch 단일 클릭, 최근 작업 전환 |
| 실행 이력·추천 | 자비스를 통한 앱 실행 이력, 이력 기반 연관 앱 추천, 승인·거절·만료 처리 |
| 일정 | 서버에 저장한 자체/Google 일정의 자연어 기간 조회, 일정 탭과 마감 할 일 읽기 전용 표시([CAL](../features/calendar.md)), Google 연결·해제와 동기화 상태. 일정 편집·할 일 변경 UI는 별도 범위 |
| 공통 기반 | 사용자·기기 인증, 기능 가용 상태, 취소·만료, 로그, 수집·삭제 설정 |

MVP에서는 자비스를 통해 수행한 앱 실행만 행동 분석 대상으로 삼는다. 사용자가 직접 실행한 모든 앱을 상시 관찰하는 기능은 확장 범위다. AR 캐릭터, 일정 생성·수정·삭제, 자유로운 화면 조작 에이전트도 MVP에 포함하지 않는다.

## 처리 원칙

- 모든 주요 기능은 로그인한 사용자만 사용한다. 앱 시작 시 인증 확인·복구를 마치기 전에는 로그인·회원가입 화면만 제공하고 센서·인식·OS 실행을 시작하지 않는다. 인증 상태와 기능 허용 기준은 [계정 인증](../features/auth.md)을 따른다. 중지·정리·앱 종료는 인증 없이 가능하다.
- 마이크 PCM 수집·호출어 감지·VAD와 영상 인식은 클라이언트에서 수행한다. 대기 중 마이크 스트림이나 원시 영상은 서버로 보내지 않는다. 호출 후 로컬 VAD가 확정한 발화 음성만 인증된 연결로 서버 STT에 전송하고, 서버가 만든 TTS 오디오를 클라이언트에서 재생한다.
- 음성 호출 기능이 켜진 대기 상태에서만 마이크 입력과 WakeWordDetector를 계속 실행한다. 호출 후에는 VAD로 발화 구간을 확정한다. 무음·취소·권한 철회된 구간은 전송하지 않는다.
- 커서 이동·클릭·추적 손실 처리·긴급 중지는 서버나 LLM의 응답을 기다리지 않는다.
- 서버는 등록된 도구를 요청하고, 클라이언트가 권한·현재 상태·요청 유효성을 검증해 실행한다.
- 대화, 제스처, 센서, 화면 상태를 분리한다. 하나의 종료가 다른 기능을 임의로 종료하지 않는다.
- 서버는 초기에는 하나의 애플리케이션 내부 모듈로 구성한다. 도표의 역할 구분이 서버 분리를 의미하지 않는다.

| --- | --- | --- | --- |
| BASE-01 | 사용자·기기 인증 | [AUTH-01~07](../features/auth.md)에 따라 로그인·회원가입·유지·로그아웃과 주요 기능 접근 제한을 제공. 서버 연결과 각 도구 요청의 사용자·대상 기기를 검증 | MVP |

| BASE-03 | 센서·권한 관리 | 카메라·마이크 사용 기능을 추적하고 마지막 사용 기능 종료 시 해제. 마이크 권한 거부·철회·장치 중지 시 PCM 수집·KWS·VAD를 중단하고 버퍼를 폐기하며 진행 중인 음성 업로드·응답을 취소하거나 늦은 결과를 폐기. 가용 상태와 해결 방법 표시 | MVP |

| BASE-05 | 오류·실행 로그 | 요청·메시지·명령·실행 시도의 상관관계로 클라이언트·서버 흐름 연결. 권한·인식·통신·실행·외부 서비스 오류와 결과 확인 불가 구분. 세부 필드는 서버 연동 원본을 따름 | MVP |
