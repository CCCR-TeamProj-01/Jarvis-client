# 캘린더

요구사항 ID: CAL-01~09.

자비스 계정 로그인은 [계정 인증](auth.md)을 따른다. 최종 서버 ERD에 따라 자비스 DB를 자체 일정·할 일의 기본 저장소로 두고 Google 일정도 자비스 데이터 구조로 가져와 저장한다. 아래 일정 조회·외부 연결은 로그인 이후의 동작이며 연결 정보와 응답은 현재 사용자·인증 세대에 연결한다. 서버 저장 모델이 클라이언트의 일정 편집·할 일 기능까지 구현됐음을 뜻하지 않는다.

## 캘린더

| CAL-03 | 일정 표현 | 월간 달력에서 날짜별 일정·할 일 미리보기와 선택한 날짜의 상세를 표시. 종일 일정의 종료일 미포함·날짜 의미, 반복 일정의 회차별 변경·취소와 시간대를 반영하고 결과 카드·음성으로 안내. Google 일정은 읽기 전용임을 구분 | MVP |
| CAL-04 | 조회·연결 상태 | 서버 조회 성공과 Google 동기화 성공을 구분. 마지막 성공 동기화 시각·인증 만료·오류를 표시하고 저장된 일정이 최신인 것처럼 안내하지 않음. 실패를 일정 없음으로 안내하지 않음 | MVP |
| CAL-05 | 연결 해제 | 서버 자격 증명 제거, 가능한 제공자 토큰 폐기, 외부 자동 동기화·대기 조회 중단. 이전 연결 응답은 버전 검증 후 폐기. 자체 일정과 Google에서 가져온 일정의 처리 범위를 구분하며 저장 사본의 보관·삭제 정책은 연동 전 확정 | MVP |
| CAL-06 | 마감 할 일 표시 | 일정 탭에서 마감 날짜 또는 마감 시각이 있는 할 일을 해당 사용자 날짜에 읽기 전용으로 표시. 날짜 마감은 시간대 변환 없이 유지하고 시각 마감은 사용자 시간대로 변환. 마감 없음은 제외하며 `pending`·실제 서버의 `open`과 `completed`를 구분. 완료·수정·삭제 UI와 알림은 제외 | MVP |
| CAL-07 | 일정 추가 | 월간·주간 달력에서 날짜를 선택하면 그 칸에 작은 `+` 버튼이 나타나고(일간 보기는 날짜 제목 옆 버튼) 누르면 그 날짜가 채워진 대화상자가 열린다. 제목·종일 여부·시작·종료를 입력해 저장하면 `source=jarvis` 일정으로 서버에 만들고 달력을 다시 조회해 보여 준다. 입력은 날짜·시각 값 그대로 Main에 전달하고 사용자 시간대 변환과 검증(제목 공백·255자, 시작<종료, 존재하지 않는 시각)은 Main만 한다. 종일 일정은 날짜 구간으로 보내며 시각으로 바꾸지 않는다. 더블클릭 추가는 제외 | MVP |
| CAL-08 | 일정 수정 | 자체 일정의 상세에서 수정 대화상자를 열어 제목·종일 여부·시작·종료를 바꾼다. 여러 날 일정은 어느 날에서 열어도 원래 시작·종료로 열리고, 종일↔시간 일정 전환은 반대쪽 필드를 비워 보낸다. Google 등 자체 일정이 아닌 출처에는 수정 버튼을 두지 않으며 서버가 거부해도(409) 이유를 안내한다 | MVP |
| CAL-09 | 일정 삭제 | 자체 일정을 확인 대화상자를 거쳐 삭제한다. 서버에서는 취소 처리이고 예약된 알림도 함께 취소되며 되돌리는 기능은 없음을 안내하되 영구 삭제로 표현하지 않는다. 이미 지워졌거나(404) 읽기 전용(409)이면 이유를 안내하고 달력을 다시 조회한다 | MVP |

## 일정 조회

사용자 발화 → 서버가 사용자 시간대 기준의 기간 확정 → 서버 저장소의 자체/Google 일정 조회와 필요한 동기화 → 반복·종일 일정 정규화 → 결과 카드·음성 안내 순서다. 외부 동기화 방식과 조회 시 동기화 여부는 [결정 목록](../delivery/validation.md#서버-erd-반영-후-결정-목록)에서 확정한다. 클라이언트는 `source=jarvis/google`, 저장된 데이터의 최신성·연결 상태를 표시할 수 있어야 한다.

조회 실패 시 마지막 성공 조회 정보가 있으면 그 시점을 표시하고 최신 조회 성공으로 오인시키지 않는다. Google 동기화에 실패했어도 자체 일정의 조회 결과와 실패 범위를 구분한다. 시간 표시의 공통 규칙은 [시각 계약](../architecture/server-integration.md#시각-계약)을 따른다. 종일 일정은 `start_date`·`end_date`의 날짜 구간이며 종료일은 포함하지 않는다. 이를 UTC 시각으로 임의 변환해 전날·다음 날로 이동시키지 않는다. 반복 일정은 서버가 회차별로 저장하며 재가져오기에서 변경·취소를 반영한다. 취소된 회차는 조회에서 제외한다.

## 저장·연결 해제와 범위

일정 원문을 장기 저장하지 않던 기존 기본안을 서버 저장 방식으로 변경한다. 보관·삭제 경계는 [데이터와 보안](../architecture/data-security.md#대화와-일정-저장)에 둔다. Google 연결을 해제했을 때 가져온 일정의 보관/삭제, 마지막 사본 표시 여부를 결정하고 UI 안내와 서버 동작을 일치시킨다. 연결 해제를 자체 일정 전체 삭제로 취급하지 않는다.

Google 연동은 단방향 가져오기다(최종 ERD 6-4절 `CALENDAR_EVENTS`). `source=google` 일정은 자비스에서 수정·삭제하지 않고 Google에서 변경한 내용을 다시 가져온다. 서버의 등록·수정·삭제 대상은 `source=jarvis` 자체 일정으로 한정한다.

할 일 완료·수정·삭제, 마감 없는 할 일 목록·알림, 반복 일정의 회차 선택(이 회차만/전체)은 CAL-01~09에 포함하지 않는다. 서버 에이전트의 대화 도구와 별개로 화면 범위를 추가할 때는 재사용하지 않은 요구사항 ID와 완료 조건을 정의한다.

## 일정 탭 구현 범위

F-039([#85](https://github.com/CCCR-TeamProj-01/Jarvis-client/issues/85))는 CAL-02·03·04의 조회 화면과 CAL-06을 구현한다. 왼쪽 일정 탭은 월간 달력(일~토)으로 열리며 월간·오늘·내일·이번 주(월~일), 이전·다음 기간과 새로고침을 제공한다. Main이 사용자 시간대와 서버 데이터를 읽어 날짜별로 나누고, Renderer는 검증된 스냅샷을 표시한다. 월 이동은 매월 첫날·말일과 윤년을 반영하며 날짜·시각 변환과 조회 범위 보정의 서버 계약은 [서버 연동](../architecture/server-integration.md#일정-조회-연동)을 따른다.

달력 날짜 칸에는 일정·할 일 미리보기 2개와 추가 건수를 표시하고, 날짜를 선택하면 전체 상세를 표시한다. 오늘 표시와 선택 표시를 구분하며 방향키·Home·End로 날짜를 이동할 수 있다. 좁은 창에서는 상세를 달력 아래에 배치한다. 선택 날짜는 표시 중인 날짜 안에서만 유지하고 기간 밖이면 오늘 또는 첫날로 전환한다. 조회 실패로 새 결과가 없으면 빈 달력을 성공 결과처럼 표시하지 않는다.

탭을 열 때 다시 조회하며 최근 30개 기간의 성공 결과만 실행 중 메모리에 보관한다. 조회 중에는 이전 결과임을 알리고, 실패 시 같은 기간의 이전 결과와 조회 날짜·시각을 표시하거나 결과를 표시할 수 없음을 알린다. 서버 설정의 시간대를 확인할 수 없으면 기기 시간대로 추측해 새 결과를 표시하지 않는다. 로그아웃·계정 전환 시 결과와 캐시를 지우고 이전 요청 응답을 폐기한다. 서버 미설정·개발용 인증 대역에서는 조회 불가를 표시한다.

자체·Google 출처와 여러 날 일정의 진행 일수, 종일·시간 일정 및 마감 할 일을 날짜별로 구분한다. 취소 일정은 숨기고 Google 사본은 읽기 전용으로 표시한다. 이 조회 API에는 Google 동기화 상태가 없어 저장 사본의 최신 동기화를 보장하지 않으며 화면에도 그 한계를 안내한다. Google 연결·동기화·해제(CAL-01·05), 자연어 기간 해석·음성 안내와 편집 화면은 이 구현 단위의 완료 범위가 아니다.

## 일정 추가·수정·삭제 구현 범위

F-040([#88](https://github.com/CCCR-TeamProj-01/Jarvis-client/issues/88))은 CAL-07~09를 구현한다. 입력은 대화상자로만 받는다. 날짜를 선택하면 그 칸에 `+` 버튼이 나타나고(월간·주간), 일간 보기에서는 날짜 제목 옆의 "일정 추가" 버튼을 쓴다. 자체 일정 행에만 수정·삭제 버튼이 있고 Google 사본과 다른 출처에는 없다. 반복 일정은 서버가 회차별로 저장하며 이 API에 반복 필드가 없어 수정·삭제는 그 회차 하나에만 적용된다.

Main이 입력을 검증하고 서버를 호출한다. 서버 호출 전에 사용자 시간대를 다시 읽어, 달력을 그린 뒤 시간대가 바뀌었으면 저장하지 않고 다시 조회한다. 저장에 성공하면 기간별로 보관한 조회 결과를 모두 지우고 현재 기간을 다시 조회한다. 결과는 저장함·저장 안 됨(사유 포함)·알 수 없음으로 구분한다. 서버는 일정 API의 `Idempotency-Key`를 처리하지 않아(2026-10-22 실서버 확인) 같은 추가를 다시 보내면 일정이 두 개 생긴다. 따라서 추가 요청은 자동으로 다시 보내지 않고, 응답을 받지 못했거나 서버 오류(5xx)로 처리 여부를 알 수 없으면 "알 수 없음"으로 알린 뒤 다시 저장하지 않고 달력을 새로 불러와 확인하게 한다. 수정·삭제는 반복해도 결과가 같아 다시 시도할 수 있다. 한 번에 한 변경만 보내며 로그아웃·계정 전환 시 진행 중인 요청을 취소하고 그 결과를 적용하지 않는다. 서버 호출의 규칙과 오류 분류는 [서버 연동](../architecture/server-integration.md#일정-추가수정삭제-연동)을 따른다.
