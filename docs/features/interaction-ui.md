# 호출과 화면

요구사항 ID: CALL-01~04, UI-01~04.

로그인·회원가입과 앱 시작 시 인증 확인은 [계정 인증](auth.md)의 AUTH-01~07을 따른다. 미로그인·인증 확인 중에는 인증 화면만 표시한다. 일반 화면·설정·호출·인식 재개는 Main의 인증 확인 이후 허용하며, 중지·정리·앱 종료 경로는 항상 유지한다.

## 호출과 화면

| ID | 기능 | 동작 기준과 완료 조건 | 범위 |
| --- | --- | --- | --- |
| CALL-01 | 음성 호출 | 음성 호출이 켜진 대기 상태에서 교체 가능한 WakeWordDetector가 설정한 한국어 호출어를 로컬 감지해 대화를 활성화. 공통 Ring Buffer의 호출 직후 음성을 첫 발화로 연계해 “자비스, …” 연속 명령을 보존. 일시 중지·권한 철회·마이크 중지 시 감지 중단 | MVP |
| CALL-02 | 제스처 호출 | 지정 동작과 유지 조건 충족 시 호출. 제어 모드 시작과 호출을 구분하고 재호출 제한 적용 | MVP |
| CALL-03 | 단축키 호출 | 기본·사용자 지정 단축키로 호출. 미로그인 상태에서는 로그인 화면으로 안내하고 주요 기능은 시작하지 않음. 등록 실패·충돌을 표시하고 대체 경로 제공 | MVP |
| CALL-04 | 트레이 제어 | 호출, 설정 열기, 인식 일시 중지·재개, 제스처 중지, 앱 종료 제공. 미로그인 상태의 일반 기능은 차단하고 로그인 화면으로 안내. 중지·종료는 항상 제공 | MVP |
| UI-01 | 상태 오버레이 | 대기·듣기·처리·응답·오류와 제스처 상태 표시. 상태 표시만으로 작업 앱 입력 포커스를 빼앗지 않음 | MVP |
| UI-02 | 임시 입력·결과 창 | 텍스트 입력이나 상세 결과가 필요할 때 표시. 사용자가 입력 창을 명시적으로 열면 포커스 허용 | MVP |
| UI-03 | 확인·추천 창 | 대상·행동·유효 상태를 표시. 닫기를 승인으로 해석하지 않음 | MVP |
| UI-04 | 설정 | 입력 장치, 호출·제스처, 음성 출력, 단축키, 계정, 기록 설정 관리 | MVP |

## 앱 실행 기반

F-009([이슈 #7](https://github.com/CCCR-TeamProj-01/Jarvis-client/issues/7))에서 아래 기반 동작을 구현했다.

- 앱은 단일 인스턴스로 실행하고 두 번째 실행·Dock 재호출은 기존 창을 다시 연다. 창을 닫으면 트레이로 숨기며, 트레이를 만들지 못한 경우에는 창을 유지해 접근 경로를 보장한다.
- 기본 호출 단축키는 `CommandOrControl+Shift+Space`다. 사용자 지정·설정 저장은 후속 작업이다. 등록 실패는 앱 상태에 남겨 화면에서 안내하고 트레이 호출을 유지한다.
- 트레이는 호출·설정·인식 일시 중지/재개·제스처 중지·종료를 제공한다. 미로그인 호출·설정·재개는 로그인 화면으로 안내하며 실제 기능을 시작하지 않는다. 현재 시작하지 않는 인식·제스처의 중지는 안전하게 수락한다.
- Main은 미로그인 상태와 로그인/회원가입 화면 전환·인식 일시 중지·앱 운영 상태를 소유한다. 로그인·회원가입 폼은 화면 틀만 제공하며 자격 증명 입력·제출은 아직 활성화하지 않는다. 실제 인증과 로그인 유지는 이슈 #5에서 연결한다.
- 창과 트레이의 명시적 앱 종료는 단축키·IPC 핸들러·상태 구독·트레이를 정리하고 종료한다. 다른 자원 정리를 한 번의 해제 실패로 중단하지 않는다.

미구현 기능은 성공이나 실행 중으로 표시하지 않는다. 구현된 공개 API와 발신자 검증은 [공통 인터페이스](../architecture/client-interfaces.md#화면과-main)를 따른다. 이 단계가 CALL·UI·BASE·AUTH 요구사항 전체의 완료를 의미하지 않는다.
