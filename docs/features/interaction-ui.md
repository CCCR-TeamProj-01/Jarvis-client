# 호출과 화면

요구사항 ID: CALL-01~04, UI-01~04.

색상·타이포·컴포넌트와 화면별 시각 기준은 [Frosted Pearl 디자인 시스템](../design/design-system.md)을 따른다. 기능·실행 상태의 원본은 이 문서와 기능별 명세다.

로그인·회원가입과 앱 시작 시 인증 확인은 [계정 인증](auth.md)의 AUTH-01~07을 따른다. 미로그인·인증 확인 중에는 인증 화면만 표시한다. 일반 화면·설정·호출·인식 재개는 Main의 인증 확인 이후 허용하며, 중지·정리·앱 종료 경로는 항상 유지한다.

## 호출과 화면

| ID | 기능 | 동작 기준과 완료 조건 | 범위 |
| --- | --- | --- | --- |
| CALL-01 | 음성 호출 | 음성 호출이 켜진 대기 상태에서 교체 가능한 WakeWordDetector가 설정한 한국어 호출어를 로컬 감지해 대화를 활성화. 공통 Ring Buffer의 호출 직후 음성을 첫 발화로 연계해 “자비스, …” 연속 명령을 보존. 일시 중지·권한 철회·마이크 중지 시 감지 중단 | MVP |
| CALL-02 | 제스처 호출 | 지정 동작과 유지 조건 충족 시 호출. 제어 모드 시작과 호출을 구분하고 재호출 제한 적용 | MVP |
| CALL-03 | 단축키 호출 | 기본·사용자 지정 단축키로 호출(로그인 상태에서는 대화를 시작하고 음성 세션을 붙임). 미로그인 상태에서는 로그인 화면으로 안내하고 주요 기능은 시작하지 않음. 등록 실패·충돌을 표시하고 대체 경로 제공 | MVP |
| CALL-04 | 트레이 제어 | 호출, 설정 열기, 인식 일시 중지·재개, 제스처 중지, 앱 종료 제공. 미로그인 상태의 일반 기능은 차단하고 로그인 화면으로 안내. 중지·종료는 항상 제공 | MVP |
| UI-01 | 상태 오버레이 | 대기·듣기·처리·응답·오류와 제스처 상태 표시. 상태 표시만으로 작업 앱 입력 포커스를 빼앗지 않음 | MVP |
| UI-02 | 임시 입력·결과 창 | 텍스트 입력이나 상세 결과가 필요할 때 표시. 사용자가 입력 창을 명시적으로 열면 포커스 허용. 텍스트 입력은 [대화](speech.md#대화와-음성-세션의-관계)에 턴으로 제출되며 음성과 같은 대화에서 섞일 수 있음. 현재는 메인 창 안의 입력란으로 제공하고 별도 임시 창은 후속 | MVP |
| UI-03 | 확인·추천 창 | 대상·행동·유효 상태를 표시. 닫기를 승인으로 해석하지 않음 | MVP |
| UI-04 | 설정 | 입력 장치, 호출·제스처, 음성 출력, 단축키, 계정, 기록 설정 관리 | MVP |

## 앱 실행 기반

F-009([이슈 #7](https://github.com/CCCR-TeamProj-01/Jarvis-client/issues/7))에서 아래 기반 동작을 구현했다.

- 앱은 단일 인스턴스로 실행하고 두 번째 실행·Dock 재호출은 기존 창을 다시 연다. 창을 닫으면 트레이로 숨기며, 트레이를 만들지 못한 경우에는 창을 유지해 접근 경로를 보장한다.
- 기본 호출 단축키는 `CommandOrControl+Shift+Space`다. 사용자 지정·설정 저장은 후속 작업이다. 등록 실패는 앱 상태에 남겨 화면에서 안내하고 트레이 호출을 유지한다.
- 트레이는 호출·설정·인식 일시 중지/재개·제스처 중지·종료를 제공한다. 미로그인 호출·설정·재개는 로그인 화면으로 안내하며 실제 기능을 시작하지 않는다. 현재 시작하지 않는 인식·제스처의 중지는 안전하게 수락한다.
- Main은 미로그인 상태와 로그인/회원가입 화면 전환·인식 일시 중지·앱 운영 상태를 소유한다. 로그인·회원가입 입력·제출과 로그인 유지는 F-012에서 구현했다([계정 인증](auth.md#클라이언트-계약과-구조)).
- 창과 트레이의 명시적 앱 종료는 단축키·IPC 핸들러·상태 구독·트레이를 정리하고 종료한다. 다른 자원 정리를 한 번의 해제 실패로 중단하지 않는다.

미구현 기능은 성공이나 실행 중으로 표시하지 않는다. 구현된 공개 API와 발신자 검증은 [공통 인터페이스](../architecture/client-interfaces.md#화면과-main)를 따른다. 이 단계가 CALL·UI·BASE·AUTH 요구사항 전체의 완료를 의미하지 않는다.

## 상태 오버레이 구현 현황

F-021([#26](https://github.com/CCCR-TeamProj-01/Jarvis-client/issues/26))에서 UI-01(상태 오버레이)을 구현했다. 시안은 디자인 캔버스 "Jarvis 화면 시안"의 4번을 따른다.

| 위치 | 책임 |
| --- | --- |
| `src/main/overlay/derive-overlay.ts` | 음성 세션 단계·요청 처리 중·제스처 모드에서 오래 유지되는 알약 내용을 계산(순수 함수) |
| `src/main/overlay/overlay-controller.ts` | 일시 표시(도구 결과·오류·일시 중지·클릭)와 유지 표시를 합쳐 바뀐 것만 보냄. 알약 ID·개정 번호·표시 시간 |
| `src/main/overlay/overlay-window.ts` | 투명·프레임 없음·항상 위·포커스 없음·마우스 통과 창. 표시할 것이 있을 때만 존재하고 활성 화면의 사용 영역을 덮음 |
| `src/main/overlay/create-overlay.ts` | 실제 창과 앱 상태·알림 연결. 개발 중에는 `JARVIS_NO_OVERLAY=1`로 끔 |
| `src/main/ipc/overlay-ipc.ts`, `src/preload/overlay-bridge.ts` | 오버레이 페이지가 받는 상태와 보낼 수 있는 두 메시지(마우스 위치, 중단)의 검증 |
| `src/renderer/overlay/` | 알약 그리기. 아이콘·문구·모션(움직임 줄이기 존중) |

- 위치는 음성·결과 알약이 화면 위쪽 가운데, 제스처 알약이 오른쪽 아래다. 제스처를 쓰는 화면이 있으면 그 화면, 없으면 주 화면에 표시한다. 메뉴 막대·Dock·작업 표시줄을 피한 사용 영역만 덮는다(macOS가 메뉴 막대 아래로 창을 밀어 아래쪽 알약이 잘리는 것을 막기 위함).
- 유지 표시: 듣는 중·후속 발화 대기(소리 막대), 인식·처리 중(도는 오브, 글 입력 요청 포함), 응답 중(중단 버튼), 제스처 `손을 찾는 중`·`포인팅`·`커서 멈춤`. 일시 표시: 도구 실행 결과 2.5초(성공)·5초(실패·오류), 인식 일시 중지 3초, 클릭 0.6초. 일시 표시가 끝나면 아래 유지 표시로 돌아가고, 아무것도 없으면 창이 숨는다.
- 마우스는 평소 모두 통과한다. 중단 버튼이 있는 알약 위에 포인터가 있을 때만 창이 마우스를 받고, 벗어나거나 버튼이 사라지면 즉시 통과로 돌아간다. 중단 요청은 Main이 발신자·내용·실제로 중단 버튼이 떠 있는지를 확인한 뒤 대화 중지로 처리한다.
- 오버레이 페이지는 표시용 값(알약 종류·문구·중단 가능 여부)만 받고 앱 상태나 인증 정보를 받지 않는다. 로그인 전에는 표시할 상태가 없어 창을 만들지 않는다.
- 확인한 범위(macOS): 일반 바탕화면과 앱 창 위에서 표시됨, 포커스를 가져가지 않음, 투명 배경, 일시 표시가 사라지면 숨음. 전체 화면 앱·다른 데스크톱(Space) 위, 중단 버튼 위 실제 마우스 동작, Windows는 아직 확인하지 못했다.
