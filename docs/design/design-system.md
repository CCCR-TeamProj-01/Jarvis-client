# JARVIS 디자인 시스템 — Frosted Pearl

버전: 1.0 · 적용 기준: 2026-10-20 · 대상: Windows / macOS Electron 클라이언트

사용자가 제공한 **Light Glassmorphism / Frosted Pearl** 명세를 현재 프로젝트에 맞춰 정리한 디자인 원본이다. 기능과 접근 권한은 [계정 인증](../features/auth.md), [호출과 화면](../features/interaction-ui.md)을 따른다. 이 문서의 미래 화면 예시는 기능 구현 완료를 뜻하지 않는다.

## 1. 원칙과 적용 범위

- **조용한 대기:** 로그인 후 호출 대기에는 불필요한 창·지속 애니메이션을 노출하지 않는다. 미로그인·인증 확인 중에는 인증 화면을 제공한다.
- **읽을 수 있는 반투명:** 긴 본문·입력·중요 결과는 높은 불투명도를 사용한다. 배경보다 텍스트·액션이 먼저 읽혀야 한다.
- **부드러운 인상:** 밝은 진주색 표면에 파란색·보라색을 제한적으로 사용한다. 네온·과도한 SF 장식·탄성 효과는 피한다.
- **실행 중심:** 진행·완료·실패·확인 필요를 텍스트와 아이콘으로 구분한다. 실행 여부는 Main이 확인한 실제 상태를 기준으로 한다.

| 구분 | 현재 적용 / 향후 기준 |
| --- | --- |
| 현재 적용(F-010) | 공통 CSS 토큰, 글꼴·아이콘, 로그인·회원가입 화면 틀, 선택·비활성·초기 로딩·연결 오류·단축키/트레이 경고, 종료 버튼 |
| 인증 기능 후속(#5) | 활성 폼, 입력 검증·중복 확인·제출·세션 복구·로그아웃·만료 안내 |
| 향후 화면 | Compact·Expanded·설정·작업 결과·확인창·제스처 상태 표시 |
| 검증 중인 네이티브 효과(F-011) | 실제 외관 문제로 기본 비활성. 개발 환경에서 명시적으로 선택하는 Vibrancy·Acrylic과 대체 동작의 구현은 남겨 두고 시각 검증 후 재검토 |

현재 구현 파일은 `src/renderer/ui/tokens.css`(값), `styles.css`(레이아웃·상태), `main.tsx`(인증 화면 틀), `src/main/application/window-material.ts`(네이티브 소재·대체 처리)다. 불투명 창 배경은 `color.background`와 맞춘다.

글꼴·아이콘의 라이선스 사본은 `src/renderer/public/licenses/`에서 관리하며 Renderer 빌드에 함께 포함한다.

## 3. 유리 표면

| 변형 | 흰색 불투명도 | Blur | 사용 |
| --- | --- | --- | --- |
| `glass.compact` | 72% | 24px | 향후 플로팅 상태 패널 |
| `glass.expanded` | 82% | 30px | 현재 인증 패널·향후 대화 패널 |
| `glass.nativeAuth` | 72% | 30px | 실험 네이티브 모드 전용. 기본 실행에서는 미사용 |
| `glass.card` | 88% | 16px | 향후 작업 결과 |
| `glass.overlay` | 78% | 28px | 향후 확인창 |
| `glass.tooltip` | 92% | 12px | 향후 툴팁·팝오버 |
| `glass.input` | 80% | 없음 | 활성 입력 표면 |

- 경계: `1px solid rgba(255,255,255,0.85)`.
- 하이라이트: `inset 0 1px 0 rgba(255,255,255,0.9)`.
- 채도: 150%. 기본 그림자: `0 12px 40px rgba(41,65,109,0.12)`.
- 유리 표면을 3단계 이상 중첩하지 않는다. 입력·긴 본문은 가독성을 우선한다.
- 기본 실행에서는 불투명한 `#F8FAFC` 네이티브 창과 앱 내부의 블루·라벤더 배경, 82% 흰색 인증 패널·CSS 블러를 사용한다. 실제 바탕화면이 비치는 효과를 제공한다고 안내하지 않는다.
- 실험 네이티브 모드에서는 Main이 소재를 적용하고 창의 콘텐츠 배경을 투명하게 한다. Renderer도 문서의 불투명 배경을 제거하고 낮은 불투명도의 색조와 72% 흰색 인증 패널을 겹친다. 이 조합의 시각 품질은 아직 완료 조건을 충족하지 않았다.
- 실험 모드의 보조 글자는 `color.nativeSecondary`(`#334155`)를 사용한다. 소재를 사용할 수 없거나 실패하면 기본 밝은 화면으로 복구하며 앱 실행을 실패시키거나 오류창을 띄우지 않는다.
- `backdrop-filter` 미지원 시 패널을 흰색으로 대체한다. `prefers-reduced-transparency: reduce` 또는 `prefers-contrast: more`에서는 배경·패널을 불투명하게 하고 블러를 제거한다.
- 앱 내 투명도 설정은 설정 기능 구현 시 연결한다. 현재 존재하지 않는 토글은 표시하지 않는다.

### OS별 소재와 대체 정책

사용자 결정에 따라 현재 디자인을 유지하고 네이티브 효과 적용은 후속 작업으로 보류한다. F-011은 재검토할 작업으로 남기며 현재 디자인 반영의 완료 조건에 포함하지 않는다.

**현재 기본값은 비활성이다.** 네이티브 API 성공과 CSS 상태 동기화 검사는 통과했지만 사용자가 실제 외관 문제를 보고했다. 전체 창의 실제 합성 결과를 검증하기 전에는 F-011을 완료 처리하거나 기본 활성화하지 않는다. 아래 동작은 개발 환경에서 `JARVIS_NATIVE_WINDOW_EFFECTS=1`로 선택하는 실험 모드에만 적용한다. 패키지 빌드는 플래그가 있어도 효과를 활성화하지 않는다. 기본 실행에서는 네이티브 소재 API를 호출하거나 테마 리스너를 등록하지 않는다.

| 환경 | 네이티브 처리 | 대체 조건 |
| --- | --- | --- |
| macOS | `setVibrancy('under-window')`, `visualEffectState: followWindow` | 투명도 감소·고대비·적용 실패 |
| Windows 11 22H2 이상 | `setBackgroundMaterial('acrylic')`. OS release의 빌드 22621 이상 확인 | 투명도 감소·고대비/강제 색상·적용 실패 |
| 이전 Windows·기타 OS·버전 판별 불가 | 네이티브 효과 API를 호출하지 않고 불투명 대체 | 항상 |

- 별도 네이티브 확장 모듈·`transparent: true`·frameless 창을 추가하지 않는다. 창 이동·크기 조절·제목 표시줄·종료 경로는 기존 동작을 따른다.
- Main은 `nativeTheme`의 투명도 감소·고대비·강제 색상 설정을 읽고 `updated`를 구독한다. 설정 변경 시 소재를 제거/복원하며 OS 설정 자체를 변경하지 않는다.
- 네이티브 API가 예외를 내면 해당 창은 불투명 모드로 유지하고 테마 이벤트마다 반복 적용하지 않는다. Renderer도 기본 밝은 배경으로 전환해 네이티브 소재 제거가 실패하더라도 내용이 읽히도록 한다.
- OS가 자체 정책으로 효과를 약화하거나 대체할 수 있어 플랫폼별 결과가 완전히 같지는 않다. 지원 조건 판별과 API 호출 성공이 모든 환경의 시각 품질을 보증하지는 않는다.
- `application.windowMaterial`의 Main 상태를 기존 IPC로 전달한다. 새 범용 OS 제어 API는 공개하지 않는다. 창 닫힘·앱 종료 시 소유한 테마 구독을 해제한다.
- Windows 실제 소재·비활성 창·화면 배율·설치 패키지는 해당 OS에서 별도 시각 검증한다. macOS의 전체 창 합성 효과도 실제 창에서 확인한다. Renderer 콘텐츠 캡처만으로 바탕화면 블러 품질을 판정하지 않는다.

## 5. 화면과 창

### 현재 인증 화면

- 네이티브 창은 현재 880×800, 최소 640×560을 유지한다. 콘텐츠 카드 최대 폭은 408px, 기본 안쪽 여백은 32px이다.
- 기본 화면에서는 카드를 가운데 배치한다. 좁거나 낮은 화면에서는 바깥 16px·안쪽 24px 여백을 사용한다. 화면보다 콘텐츠가 길어지면 문서 전체를 스크롤하여 안내·종료 경로에 접근한다.
- 구성 순서: 브랜드 → 제목·설명 → 로그인/회원가입 전환 → 연결 상태 → 폼 → 기능 준비 안내 → 운영 경고 → 호출 단축키·앱 종료.
- 화면 전환은 기존 `auth.open` 명령과 Main 스냅샷을 따른다. 현재 폼 입력·중복 확인·제출은 비활성이다. 준비 안내를 폼과 `aria-describedby`로 연결한다.
- 로그인에는 아이디·비밀번호, 가입에는 아이디·중복 확인·비밀번호·재입력을 배치한다. 실제 필드 정책과 완료 동작은 인증 원본 명세를 따른다.
- 네이티브 제목 표시줄·기존 창 닫기/트레이 동작을 유지한다. `앱 종료`는 명시적 프로세스 종료다.

### 후속 화면 기준

| 화면 | 권장 크기 | 구성·행동 |
| --- | --- | --- |
| Idle | 창 없음 | 로그인한 사용자의 호출 대기. 센서 사용은 실제 활성 상태만 표시 |
| Compact | 폭 380px, 높이 약 76~120px | 오브·상태·음성 파형·닫기·확장. 화면 작업 영역 안에 배치 |
| Expanded | 폭 460px, 높이 약 620px | 헤더·대화/결과·입력. 콘텐츠 영역만 스크롤 |
| Settings | 760×600 | 좌측 내비게이션·우측 설정. 일반 대화창보다 불투명한 표면 |

이 크기를 현재 인증 창의 최소 크기에 바로 적용하지 않는다. 네이티브 창 전환·다중 모니터 작업 영역 제한은 해당 화면 구현 시 연결한다.

후속 창 동작 기준:

- 상태 오버레이만으로 포커스를 가져오지 않는다. 입력·설정 등 사용자가 명시적으로 연 화면에 포커스를 준다.
- 초기 플로팅 위치는 화면 작업 영역 오른쪽 아래를 기준으로 하고 작업 표시줄·Dock을 침범하지 않도록 한다. 사용자 이동 위치의 저장·복원은 창 배치 구현 단계에서 결정한다.
- Compact → Expanded는 같은 화면 가장자리 기준을 유지한다. 창 크기는 작업 영역을 넘지 않게 제한한다.
- 닫기·Esc는 작업 승인으로 해석하지 않는다. 확인창의 dismiss 처리는 기존 확인 계약을 따른다. 창을 숨기는 행동과 실행 취소는 별도로 표시한다.
- 드래그 영역·항상 위 표시·크기 조절은 화면 역할에 맞게 Main에서 구현한다. 현재 인증 창에 별도의 frameless·항상 위 동작을 추가하지 않는다.

## 6. 아이콘과 컴포넌트

아이콘은 **Lucide React**, Outline 스타일, 기본 20px·작은 아이콘 16px·큰 아이콘 24px, 선 굵기 1.75~2를 사용한다. 텍스트와 함께 쓰는 장식 아이콘은 `aria-hidden` 처리하고 아이콘만 있는 버튼에는 접근 가능한 이름과 툴팁을 제공한다.

### 버튼

기본 높이 40px, Radius 12px. Disabled에는 Hover·Pressed 효과를 적용하지 않는다.

| 종류 | Default | Hover | Pressed |
| --- | --- | --- | --- |
| Primary | action 배경·흰색 글자 | actionHover | actionPressed |
| Secondary | 흰색 65%·controlBorder·textPrimary | primarySoft·action 글자 | primarySoft·actionPressed 글자 |
| Ghost | 투명·textSecondary | primarySoft·action 글자 | primarySoft·actionPressed 글자 |
| Danger(후속) | dangerText 배경·흰색 글자 | 더 진한 오류색 | 더 진한 오류색 |

- 공통 Disabled: disabledBackground·disabledText·border. 현재 인증 제출 버튼은 이 상태다.
- Focus: action 2px 외곽선, offset 3px. 색 변화 외에도 윤곽으로 구분한다.
- 향후 요청 중 버튼은 작업명과 진행 상태를 함께 표시하고 중복 제출을 막는다.
- 앱 종료는 일반 Ghost 액션이다. 데이터 삭제 등 파괴적 작업에 Danger를 사용한다.

### 입력·전환·안내

- 입력 높이 44px, Radius 12px, 내부 가로 여백 12px, 활성 경계 controlBorder, Focus는 action 외곽선이다.
- Disabled 입력은 background·border를 사용하며 실제 입력이 가능해 보이지 않도록 준비 안내를 병행한다.
- 향후 오류 입력은 dangerText 경계·텍스트와 필드 아래 오류 문구, `aria-invalid`·설명 연결을 제공한다. 중복 확인 성공은 아이콘·문구와 함께 표현한다.
- 계정 전환은 이름 있는 버튼 그룹으로 제공하고 `aria-pressed`와 밝은 선택 표면·파란색 글자로 현재 화면을 구분한다. ARIA tab 역할을 사용한다면 화살표 키 이동 등 tab 동작도 함께 구현해야 한다.
- 안내는 Info, 오류는 CircleAlert, 경고는 TriangleAlert와 문구를 함께 사용한다. 단축키·트레이 실패는 경고이며 인증 실패로 표시하지 않는다.
- 초기 준비·운영 경고는 `role=status`, 연결 오류는 `role=alert`로 알리고 재연결 버튼을 제공한다. 단축키는 `kbd`로 표시한다.

### 후속 컴포넌트

- **Chat Composer:** 최소 높이 88px, Radius 20px, 텍스트·음성·전송. 입력 최대 높이를 넘으면 입력 내부 스크롤. 이미지 첨부는 기능 범위와 전송 계약이 확정된 뒤 제공한다.
- **Action Card:** 아이콘·작업명·대상·상태·결과가 필수다. 미리보기·상세·추가 액션은 실제 데이터가 있을 때 제공한다. 되돌리기는 해당 작업이 실제로 지원할 때만 제공한다.
- **Dialog:** glass.overlay, 대상·행동·영향·확인/취소를 명확히 표시한다. 유효 기간과 승인 처리는 기존 확인 계약을 따른다. 포커스 진입·복귀·이탈 제한과 Esc 동작을 함께 구현한다.

### 상태 오버레이 알약

창을 열지 않아도 보이는 상태 표시는 높이 44 px의 알약이다. 배경은 `glass-overlay`(약 90 % 불투명)와 `blur-overlay`, 그림자는 패널보다 진하게 둬 어떤 바탕에서도 읽히게 한다. 왼쪽 28 px 원형 배지에 아이콘이나 소리 막대·오브를 두고 오른쪽에 문구를 쓴다. 의미는 문구가 전하고 배지는 보조다(색에만 의존하지 않음). 배지 색은 듣는 중 민트, 처리 중 `gradient.orb`, 응답·클릭 보조 보라, 성공 초록, 오류 빨강, 가리키는 중 파랑, 멈춤·찾는 중·일시 중지 회색을 쓴다. 모션은 나타날 때 220 ms 한 번과 오브 회전·소리 막대뿐이며 움직임 줄이기 설정에서는 모두 끈다.

## 7. 실행 상태 표현

아래는 표시 규칙이다. 대화·요청·음성·제스처의 독립 상태를 하나의 실행 상태로 대체하지 않는다. 실제 상태와 결과를 조합해 표현하며 `terminal`만으로 성공을 추정하지 않는다.

| 시각 상태 | 표현 | 연결 기준 |
| --- | --- | --- |
| Idle | 정적인 오브·대기 문구 | 인증 완료 후 실제 호출 대기 |
| Listening | 파란색·실제 음량 파형·듣는 중 | 실제 음성 캡처 상태 |
| Processing | 보라색·느린 맥동·처리 중 | 요청 processing |
| Executing | 파란색·진행 표시·실행 중 | 요청 executing |
| Responding | 음성/텍스트 응답 표시·중지 경로 | 실제 출력 재생·응답 상태 |
| Success | 초록색·체크·완료 문구 | 확인된 성공 결과 |
| Warning | 황색·확인/주의 문구 | awaiting_confirmation·운영 경고 |
| Error | 빨간색·오류 문구·복구 경로 | 확인된 실패·client.error |

제스처 활성 여부·센서 사용·인식 일시 중지·오프라인·인증 복구는 각 상태로 병행 표시한다. 로그인 화면의 정적인 브랜드 오브에는 듣기·처리 애니메이션을 사용하지 않는다.

## 8. 모션·접근성·플랫폼

| 모션 | 시간 | 적용 |
| --- | --- | --- |
| 버튼 피드백 | 140ms (원안 120~160ms) | 현재 배경·색상·그림자 전환 |
| Compact 표시 | 220ms | 후속 |
| 패널 확장 | 280ms | 후속 |
| 결과 카드 진입 | 200ms (원안 180~240ms) | 후속 |
| 확인창 | 200ms | 후속 |
| 오브 호흡 | 2.4초 | 실제 AI 상태를 표현할 때만 후속 적용 |

- Ease-out을 기본으로 하고 과도한 탄성·상시 장식 애니메이션을 피한다. 음성 파형은 실제 음량에 반응해야 한다.
- `prefers-reduced-motion: reduce`에서는 현재 버튼 전환을 제거한다. 향후 모션도 같은 환경 설정을 따른다.
- 일반 텍스트는 최종 합성 배경과 4.5:1, 중요한 아이콘·컨트롤 경계는 3:1 이상을 기준으로 확인한다. 반투명 표면은 지정 색상 값만으로 판정하지 않는다.
- 클릭 대상은 가능한 40×40px 이상, 모든 주요 액션은 키보드로 조작 가능하게 한다. 포커스를 숨기지 않고 색상만으로 상태를 전달하지 않는다.
- 화면 배율·작은 창에서는 내용 잘림 대신 스크롤·줄바꿈을 제공한다. 강제 색상 모드는 시스템 색상 처리를 허용한다.
- Windows·macOS에서 브랜드·타이포·컴포넌트를 공유한다. 네이티브 제목 표시줄·권한 UI·Dock/트레이·네이티브 소재는 플랫폼 역할에 맞춰 별도로 처리한다.
- 기본 창은 두 플랫폼에서 공통 밝은 표면을 사용한다. 실험 중인 Vibrancy·Acrylic은 실제 OS별 창 외관 검증 후 적용 여부를 정한다. 앱 자체의 다크 테마 전환은 현재 범위에 포함하지 않는다.

## 9. 현재 화면 확인 기준

- 로그인·가입 전환 시 같은 토큰·정렬·입력 규격을 사용한다.
- 기본 창과 최소 창에서 가로 넘침 없이 폼·안내·종료 버튼에 접근한다.
- 키보드 이동 시 전환·종료·재시도 버튼의 포커스가 보인다. 비활성 필드를 활성 입력으로 안내하지 않는다.
- 연결 오류·단축키 실패·트레이 실패가 텍스트와 아이콘으로 구분된다. 오류가 늘어나도 내용이 겹치지 않는다.
- 글꼴·아이콘이 앱 빌드에 포함되고 외부 CDN을 요구하지 않는다.
- 앱 시작 배경에 기존 어두운 색이 남지 않는다. 일반 종료·트레이·IPC·인증 접근 제한을 유지한다.
- Main의 소재 값과 문서의 투명/불투명 상태가 일치한다. 기본 실행과 패키지에서 네이티브 효과가 꺼져 있고 창과 바깥 배경이 밝게 유지되는지 확인한다. 접근성 설정에서는 CSS 반투명도 제거한다.
